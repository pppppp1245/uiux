📋 팝업 (Popup)

jQuery를 사용하여 팝업 창을 여는 예제입니다.

이용약관 팝업

아래 버튼을 클릭하면 팝업 창이 열립니다.

HTML
<!-- 팝업 실행 버튼 -->
<button id="openPopup" class="btn btn-primary">이용약관 보기</button>
jQuery
// 팝업 기능
$('#openPopup').on('click', function() {
    var url = "popup.html";
    var name = "TermsPopup";
    
    var width = 500;
    var height = 600;
    var left = (window.screen.width / 2) - (width / 2);
    var top = (window.screen.height / 2) - (height / 2);
    
    var options = "width=" + width + ", height=" + height + ", top=" + top + ", left=" + left + ", resizable=no, scrollbars=yes, status=no, toolbar=no";
    
    window.open(url, name, options);
});

🔔 알럿 (Alert)

jQuery를 사용하여 알럿 메시지를 표시하는 예제입니다. (모바일에서만 가능)

성공 메시지 알럿

아래 버튼을 클릭하면 알럿이 나타납니다.

HTML
<!-- 알럿 컨테이너 (오른쪽 상단 배치) -->
<div id="alertContainer" class="alert-container">
    <div class="alert-box success">
        <span class="icon">✔</span>
        <span class="message">데이터가 성공적으로 저장되었습니다.</span>
        <span class="close-btn">&times;</span>
    </div>
</div>
CSS
.alert-container {
    position: fixed;
    top: 20px;
    right: 20px;
    z-index: 9999;
}

.alert-box {
    display: none;
    min-width: 300px;
    padding: 16px 20px;
    background: rgba(255, 255, 255, 0.9);
    backdrop-filter: blur(10px);
    border-left: 5px solid #4CAF50;
    box-shadow: 0 4px 15px rgba(0,0,0,0.1);
    border-radius: 8px;
    color: #333;
    display: flex;
    align-items: center;
    gap: 12px;
    margin-bottom: 10px;
}
jQuery
// 알럿 기능
$('#triggerAlert').on('click', function() {
    var $alert = $('.alert-box');

    $alert.css({ 'right': '-100px', 'opacity': '0', 'display': 'flex' })
          .animate({ 'right': '0', 'opacity': '1' }, 300);

    setTimeout(function() {
        $alert.fadeOut(300);
    }, 3000);
});

// 닫기 버튼 클릭 시
$('.close-btn').on('click', function() {
    $(this).parent().fadeOut(200);
});

🍞 토스트 (Toast)

jQuery를 사용하여 토스트 메시지를 표시하는 예제입니다. (모바일에서만 가능)

작업 완료 토스트

아래 버튼을 클릭하면 토스트가 나타납니다.

HTML
<!-- 토스트가 담길 컨테이너 -->
<div id="toastContainer" class="toast-container"></div>
CSS
.toast-container {
    position: fixed;
    bottom: 30px;
    left: 50%;
    transform: translateX(-50%);
    z-index: 10000;
}

.toast-item {
    min-width: 250px;
    background: rgba(33, 33, 33, 0.9);
    color: #fff;
    padding: 14px 24px;
    border-radius: 50px;
    margin-top: 10px;
    font-size: 14px;
    text-align: center;
    box-shadow: 0 8px 16px rgba(0,0,0,0.2);
    display: none;
}
jQuery
// 토스트 기능
$('#showToast').on('click', function() {
    var $toast = $('<div class="toast-item">성공적으로 처리되었습니다!</div>');
    
    $('#toastContainer').append($toast);
    $toast.fadeIn(400).delay(2000).fadeOut(400, function() {
        $(this).remove();
    });
});

    $('#sheetOverlay').fadeIn(200);
    $('#bottomSheet').addClass('active');

    $('#bottomSheet').removeClass('active');
    $('#sheetOverlay').fadeOut(300);
}

$('.close-sheet, #sheetOverlay').on('click', function(e) {
    if ($(e.target).is('#sheetOverlay') || $(e.target).is('.close-sheet')) {
        closeSheet();
    }
});

📝 텍스트 필드 (Text Field)

이름, 이메일, 주소 등을 입력받을 때 사용하는 기본적인 입력 필드입니다.

입력 필드 컴포넌트 예시

이메일 입력 필드

이메일을 입력하고 필드를 벗어나면 유효성 검사가 실행됩니다.

정확한 이메일 형식을 입력해주세요.

HTML
<div class="input-group">
    <label for="userEmail">이메일 주소</label>
    <input type="email" id="userEmail" placeholder="example@mail.com">
    <p class="helper-text">정확한 이메일 형식을 입력해주세요.</p>
</div>
CSS
.input-group { margin-bottom: 20px; width: 300px; }
label { display: block; margin-bottom: 8px; font-weight: bold; font-size: 14px; }

input[type="email"] {
    width: 100%;
    padding: 12px;
    border: 1px solid #ddd;
    border-radius: 8px;
    outline: none;
    transition: all 0.2s;
}

/* 포커스 시 디자인 변화 */
input[type="email"]:focus {
    border-color: #007AFF;
    box-shadow: 0 0 0 3px rgba(0, 122, 255, 0.1);
}

/* 에러 상태 클래스 */
.input-group.error input { border-color: #f44336; }
.input-group.error .helper-text { color: #f44336; }
jQuery
$(document).ready(function() {
    $('#userEmail').on('blur', function() {
        var email = $(this).val();
        var emailReg = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
        
        if (!emailReg.test(email) && email !== "") {
            $(this).parent().addClass('error');
            $('.helper-text').text('유효하지 않은 이메일 형식입니다.');
        } else {
            $(this).parent().removeClass('error');
            $('.helper-text').text('정확한 이메일 형식을 입력해주세요.');
        }
    });
});

☑️ 체크박스 & 라디오 버튼 (Checkbox & Radio Button)

여러 선택지 중 하나 또는 그 이상을 선택할 때 사용합니다.

라디오 버튼 컴포넌트 예시

체크박스 소개

체크박스(Checkbox)는 사용자로부터 '예/아니오'의 답변을 듣거나, 여러 선택지 중 하나 이상을 선택(다중 선택)받을 때 사용하는 가장 고전적이면서도 필수적인 UI 요소입니다.

UI/UX 디자인: 체크박스를 사용하는 이유

  • 다중 선택 (Multiple Selection): 라디오 버튼과 달리 여러 항목을 동시에 선택할 수 있습니다.
  • 독립적 상태: 각 체크박스는 다른 체크박스에 영향을 주지 않고 개별적인 On/Off 상태를 가집니다.
  • 계층 구조 표현: '전체 동의'라는 부모 체크박스를 통해 여러 개의 자식 체크박스를 한 번에 제어하는 직관적인 구조를 만들 수 있습니다.
  • 명시적 확인: 약관 동의처럼 사용자의 확실한 의사 표시가 필요한 곳에 적합합니다.

체크박스의 3가지 상태 (States)

  • Unselected (미선택): 비어 있는 상태
  • Selected (선택됨): 체크 표시가 나타난 상태
  • Indeterminate (부분 선택): 전체 선택 체크박스에서 하위 항목 중 일부만 선택되었을 때 나타나는 상태입니다. 보통 '-' 모양으로 표시됩니다.

전체 동의 체크박스 (커스텀 디자인)

전체 동의를 클릭하면 모든 항목이 선택되고, 개별 항목을 선택하면 전체 동의 상태가 자동으로 동기화됩니다.

HTML
<div class="check-group">
    <!-- 전체 선택 -->
    <label class="check-item all">
        <input type="checkbox" id="checkAll">
        <span class="box"></span> 전체 동의
    </label>
    <hr>
    <!-- 개별 선택 -->
    <label class="check-item">
        <input type="checkbox" class="sub-check">
        <span class="box"></span> 서비스 이용약관 (필수)
    </label>
    <label class="check-item">
        <input type="checkbox" class="sub-check">
        <span class="box"></span> 개인정보 처리방침 (필수)
    </label>
</div>
CSS
/* 기본 체크박스 숨기기 */
.check-item input { display: none; }

.check-item { display: flex; align-items: center; cursor: pointer; margin-bottom: 10px; }

/* 커스텀 박스 디자인 */
.box {
    width: 20px; height: 20px;
    border: 2px solid #ddd; border-radius: 4px;
    margin-right: 10px; position: relative;
    transition: all 0.2s;
}

/* 체크되었을 때 스타일 */
.check-item input:checked + .box {
    background-color: #007AFF;
    border-color: #007AFF;
}

/* 체크 마크 (v) 구현 */
.check-item input:checked + .box::after {
    content: ''; position: absolute;
    left: 6px; top: 2px;
    width: 5px; height: 10px;
    border: solid white;
    border-width: 0 2px 2px 0;
    transform: rotate(45deg);
}
jQuery
$(document).ready(function() {
    // 전체 선택 클릭 시
    $('#checkAll').on('change', function() {
        $('.sub-check').prop('checked', $(this).prop('checked'));
    });

    // 개별 선택 클릭 시 전체 선택 상태 동기화
    $('.sub-check').on('change', function() {
        var allCount = $('.sub-check').length;
        var checkedCount = $('.sub-check:checked').length;

        if (allCount === checkedCount) {
            $('#checkAll').prop('checked', true);
        } else {
            $('#checkAll').prop('checked', false);
        }
    });
});

📑 탭 (Tab)

방대한 양의 콘텐츠를 논리적인 카테고리로 분류하여 효율적으로 표시할 때 사용합니다.

탭 소개

탭은 여러 레이어의 정보를 수평으로 겹쳐서 배치하여 사용자가 쉽게 정보를 탐색할 수 있게 하는 UI 컴포넌트입니다.

UI/UX 디자인: 탭을 사용하는 이유

  • 정보 구조화: 방대한 양의 콘텐츠를 논리적인 카테고리로 분류하여 사용자가 정보를 한눈에 파악하기 쉽게 만듭니다.
  • 공간 효율성: 여러 레이어의 정보를 수평으로 겹쳐서 배치하므로, 수직 스크롤을 획기적으로 줄여줍니다.
  • 맥락 유지: 전체 페이지 새로고침 없이 내용만 바뀌므로 사용자가 현재 탐색 중인 흐름을 깨뜨리지 않습니다.
  • 즉각적인 비교: 사용자가 여러 탭을 오가며 정보를 대조하거나 선택하기 편리합니다.

제품 정보 탭 (인터랙티브 데모)

탭을 클릭하여 내용을 전환해보세요.

  • 제품 정보
  • 상세 사양
  • 사용자 리뷰

제품 정보

이 제품은 최신 UI/UX 트렌드를 반영하여 설계되었습니다. 직관적인 인터페이스와 세련된 디자인으로 사용자 경험을 극대화합니다.

상세 사양

사용자 리뷰

📁 아코디언 (Accordion)

제한된 화면 공간에서 많은 양의 정보를 효율적으로 정리하여 보여줄 때 사용합니다.

아코디언 소개

아코디언(Accordion) 디자인은 마치 악기 아코디언처럼 콘텐츠를 수직으로 접었다 폈다(Expand/Collapse) 할 수 있는 UI 컴포넌트입니다. 제한된 화면 공간에서 많은 양의 정보를 효율적으로 정리하여 보여줄 때 필수적인 요소입니다.

UI/UX 디자인: 아코디언을 사용하는 이유

  • 시각적 노이즈 감소: 사용자가 당장 필요하지 않은 상세 정보는 숨겨두고, 핵심 제목(Header)만 보여줌으로써 첫인상을 깔끔하게 유지합니다.
  • 수직 공간 절약: 페이지가 불필요하게 길어지는 것을 방지하여 사용자가 끝없이 스크롤 해야 하는 피로감을 줄여줍니다.
  • 정보 탐색의 효율성: 사용자가 원하는 질문이나 항목만 골라서 열어볼 수 있게 하여 탐색 속도를 높여줍니다.
  • 점진적 정보 공개(Progressive Disclosure): 복잡한 정보를 한꺼번에 쏟아내지 않고, 사용자가 원할 때만 단계적으로 정보를 제공하는 UX 심리학을 충실히 따릅니다.

아코디언의 주요 구성 요소

  • 헤더(Header): 항목의 제목이 담긴 부분입니다. 클릭 시 본문이 열리는 트리거 역할을 합니다.
  • 아이콘(Icon): 주로 화살표(Chevron)나 플러스(+) 기호를 사용합니다. 현재 열려 있는지(Up) 닫혀 있는지(Down) 상태를 시각적으로 알려줍니다.
  • 패널(Panel): 헤더를 클릭했을 때 나타나는 상세 내용 영역입니다.

카드 소개

UI/UX 디자인: 카드 형태를 사용하는 이유

  • 정보의 독립성: 각 카드가 하나의 개별적인 주제나 상품을 나타내므로, 정보 간의 구분이 명확합니다.

카드의 핵심 구성 요소

  • 미디어(Media): 카드 상단에 위치하는 이미지나 영상. 시선을 끄는 역할을 합니다.

CTA 소개

CTA(Call to Action, 행동 유도) 디자인은 사용자에게 "이 버튼을 눌러보세요!"라고 명확하게 요청하여 특정 행동(구매, 가입, 다운로드 등)을 이끌어내는 마케팅적 UI 요소입니다. 웹사이트나 앱의 존재 목적(매출, 회원 확보)을 달성하는 데 가장 결정적인 역할을 합니다.

UI/UX 디자인: CTA가 중요한 이유

  • 목표 달성의 핵심: 사용자가 웹사이트에서 헤매지 않고, 서비스가 원하는 최종 단계(결제 등)로 넘어가게 하는 '가이드' 역할을 합니다.
  • 의사결정 보조: 사용자가 고민하는 순간, 명확한 문구와 눈에 띄는 디자인으로 행동의 근거를 제공합니다.
  • 전환율(Conversion Rate) 향상: 잘 설계된 CTA 버튼 하나가 비즈니스의 성패를 가를 만큼 강력한 영향력을 미칩니다.

CTA 디자인의 3대 원칙

  • 시각적 대비(Contrast): 주변 요소보다 훨씬 눈에 띄어야 합니다. 가장 강렬한 브랜드 컬러를 사용하세요.
  • 명확한 문구(Microcopy): "확인"이나 "제출" 같은 모호한 단어보다 "30일간 무료 체험하기", "지금 바로 50% 할인받기"처럼 구체적인 이득을 명시하세요.
  • 적절한 위치: 사용자가 정보를 다 읽고 행동할 준비가 된 시점(스크롤 하단)이나, 언제든 누를 수 있는 고정된 위치(상단 내비게이션 등)에 배치해야 합니다.

UI/UX 디자인: 캐러셀을 사용하는 이유

  • 공간 효율성: 화면의 최상단(Hero Section) 같은 금싸라기 땅에 여러 개의 중요한 메시지나 프로모션을 겹쳐서 배치할 수 있습니다.

  • 콘텐츠 큐레이션: 서비스에서 가장 강조하고 싶은 핵심 콘텐츠들을 요약해서 보여주기에 최적입니다.

  • 인디케이터(Indicators/Dots): 전체 슬라이드 개수와 현재 위치를 점(Dot)이나 숫자로 나타냅니다.

🖼️ 라이트박스 (Lightbox)

이미지를 클릭했을 때 주변 배경을 어둡게 처리하면서 해당 콘텐츠를 화면 중앙에 크게 띄워 집중시키는 UI 컴포넌트입니다.

라이트박스 소개

라이트박스(Lightbox) 디자인은 특정 이미지나 콘텐츠를 클릭했을 때, 주변 배경을 어둡게 처리(Overlay)하면서 해당 콘텐츠를 화면 중앙에 크게 띄워 집중시키는 UI 컴포넌트입니다. 사용자가 현재 페이지를 떠나지 않고도 상세 내용을 깊이 있게 확인할 수 있도록 돕는 일종의 '모달(Modal) 윈도우'의 한 형태입니다.

UI/UX 디자인: 라이트박스를 사용하는 이유

  • 몰입감 증대: 주변의 복잡한 UI 요소들을 어둡게 가림으로써 사용자가 보고 있는 이미지나 영상에만 완벽하게 집중하게 만듭니다.
  • 맥락 유지: 상세 페이지로 새로고침하여 이동하는 것이 아니라, 현재 위치 위로 창을 띄우는 것이기 때문에 탐색 흐름이 끊기지 않습니다.
  • 공간 제약 극복: 목록에서는 작은 썸네일로 보여주고, 상세 정보는 라이트박스를 통해 고해상도로 제공할 수 있어 디자인적 효율이 높습니다.

라이트박스의 핵심 구성 요소

  • 오버레이(Overlay/Dimmer): 기존 화면을 가리는 반투명한 검은색 배경입니다.
  • 스테이지(Stage): 메인 이미지나 영상이 출력되는 중앙 영역입니다.
  • 닫기 버튼(Close Button): 주로 우측 상단에 'X' 표시로 위치하여 사용자가 언제든 복귀할 수 있게 합니다.
  • 캡션(Caption): 이미지 하단에 붙는 제목이나 추가 설명입니다.

🖼️ 갤러리 (Gallery)

여러 장의 이미지나 시각적 콘텐츠를 체계적인 레이아웃으로 배열하여 사용자가 한눈에 훑어보고 탐색할 수 있도록 만든 인터페이스입니다.

갤러리 소개

갤러리(Gallery) 디자인은 여러 장의 이미지나 시각적 콘텐츠를 체계적인 레이아웃으로 배열하여 사용자가 한눈에 훑어보고 탐색할 수 있도록 만든 인터페이스입니다. 단순한 이미지 나열을 넘어, 서비스의 성격(포트폴리오, 커머스, SNS 등)에 따라 정보를 구성하는 방식이 달라집니다.

갤러리 디자인의 주요 레이아웃 유형

  • 그리드 갤러리 (Grid Gallery): 모든 이미지를 동일한 크기의 정사각형이나 직사각형 박스에 배치합니다. 질서 정연하고 깔끔한 느낌을 주며, 제품 목록이나 인스타그램 프로필 페이지에 주로 쓰입니다.
  • 메이슨리 갤러리 (Masonry Gallery): 이미지의 가로 길이는 고정하되, 세로 길이는 원본 비율에 따라 다르게 배치하는 방식입니다. '벽돌 쌓기' 방식이라고도 하며, 핀터레스트(Pinterest)가 대표적입니다. 시각적으로 역동적이고 지루하지 않습니다.
  • 슬라이딩/필름스트립 갤러리 (Sliding Gallery): 한 번에 하나 혹은 소수의 이미지만 보여주며 가로로 넘겨보는 방식입니다. 공간이 좁은 모바일이나 메인 히어로 섹션에 적합합니다.

갤러리 UI 디자인의 핵심 요소

  • 썸네일(Thumbnail): 원본보다 작은 크기의 이미지로, 빠른 로딩과 전체적인 탐색을 돕습니다.
  • 호버 효과(Hover Effect): 마우스를 올렸을 때 이미지가 커지거나, 제목/설명이 나타나는 등의 피드백을 주어 클릭을 유도합니다.
  • 필터 및 정렬 (Filtering & Sorting): 사용자가 원하는 카테고리나 최신순 등으로 콘텐츠를 걸러볼 수 있게 합니다.
  • 라이트박스 연결: 썸네일을 클릭했을 때 앞서 배운 라이트박스 형태로 원본 이미지를 크게 보여주는 것이 일반적인 패턴입니다.

💬 툴팁 (Tooltip)

툴팁(Tooltip) 디자인은 사용자가 특정 요소에 마우스를 올리거나(Hover), 포커스를 두었을 때 나타나는 작은 정보 창입니다. 인터페이스를 깔끔하게 유지하면서도 필요한 순간에만 보충 설명을 제공하는 '친절한 가이드' 역할을 합니다.

1. UI 디자인 특징

  • 말풍선 형태: 본문과 구분되도록 주로 작은 화살표(Tail)가 달린 상자 모양으로 디자인됩니다.
  • 시각적 대비: 배경색과 대비되는 색상(어두운 배경에 흰 글씨 등)을 사용하여 시인성을 높입니다.
  • 간결한 텍스트: 툴팁은 긴 문장이 아닌, 한눈에 읽히는 짧은 단어나 문구로 구성합니다.
  • 일시적 노출: 마우스를 떼면 즉시 사라지는 것이 기본이며, 본문 콘텐츠를 가리지 않는 적절한 위치(상, 하, 좌, 우)에 배치됩니다.

2. 사용 목적 및 UX 효과

  • 공간 효율성: 화면에 모든 텍스트를 다 적으면 디자인이 지저분해집니다. 중요도가 낮지만 설명이 필요한 부분에 사용하여 화면을 비워둡니다.
  • 아이콘 의미 전달: 아이콘만으로는 기능을 이해하기 어려운 경우(예: 설정, 휴지통, 물음표 아이콘), 툴팁을 통해 텍스트 설명을 제공합니다.
  • 학습 비용 감소: 사용자가 기능을 추측하지 않고 즉석에서 정보를 확인하게 하여 서비스 이용의 어려움을 줄여줍니다.

3. 디자인 시 고려할 핵심 포인트

  • 트리거(Trigger) 명시: 사용자가 툴팁이 나올 곳이라는 것을 예측할 수 있게 점선 밑줄이나 물음표 아이콘(?) 등을 활용하는 것이 좋습니다.
  • 지연 시간(Delay): 마우스가 스쳐 지나갈 때마다 툴팁이 번쩍거리며 나타나면 피로감을 줍니다. 아주 짧은 찰나(약 0.3~0.5초)의 지연 시간을 두어 의도적인 호버링에만 반응하게 하는 것이 매너입니다.
  • 모바일 배려: 모바일에는 '마우스 호버'가 없습니다. 따라서 모바일에서는 터치 시 나타나게 하거나, 툴팁 대신 하단에서 올라오는 '바텀 시트(Bottom Sheet)'로 대체하기도 합니다.
  • 방향 자동 조절: 화면 끝부분에 있는 요소의 툴팁이 화면 밖으로 잘리지 않도록, 위치에 따라 상단이나 하단으로 자동으로 바뀌어 나타나게 설계해야 합니다.

4. 툴팁의 종류

  • 일반 툴팁: 단순 텍스트 정보 제공.
  • 인터랙티브 툴팁: 툴팁 내부에 링크나 버튼이 포함되어 추가 행동을 유도하는 형태.
  • 온보딩 툴팁: 처음 접속한 사용자에게 기능 위치를 하나씩 짚어주며 설명하는 투어 가이드 형태.

📍 브레드크럼 (Breadcrumb)

브레드크럼(Breadcrumb)은 사용자가 서비스 내에서 현재 어디에 위치해 있는지, 그리고 최상위 페이지부터 현재 페이지까지의 경로가 어떻게 되는지 시각적으로 보여주는 보조 내비게이션입니다.

동화 '헨젤과 그레텔'에서 길을 잃지 않기 위해 떨어뜨린 빵 부스러기에서 이름을 따왔습니다.

1. UI 디자인 특징

  • 텍스트 나열: 보통 메인 > 대분류 > 중분류 > 현재 페이지와 같이 계층 구조를 텍스트로 나열합니다.
  • 구분자(Separator): 항목 사이에 >, /, | 같은 기호를 넣어 단계가 구분됨을 나타냅니다.
  • 링크 결합: 현재 페이지를 제외한 이전 경로들은 모두 클릭 가능한 링크로 구성하여 상위 단계로 즉시 이동할 수 있게 합니다.
  • 시각적 위계: 현재 페이지는 보통 굵게(Bold) 표시하거나 색상을 다르게 하여 경로의 끝임을 명확히 합니다.

2. 사용 목적 및 UX 효과

  • 현재 위치 파악: 사용자가 검색이나 외부 링크를 통해 페이지에 바로 진입했을 때, 이 페이지가 사이트의 어느 계층에 속해 있는지 즉시 알 수 있게 합니다.
  • 탐색 경로 단축: '뒤로 가기' 버튼을 여러 번 누를 필요 없이, 원하는 상위 카테고리로 단 한 번의 클릭만으로 이동할 수 있습니다.
  • 사이트 구조 시각화: 서비스의 전체적인 카테고리 구조를 사용자에게 학습시키는 효과가 있습니다.
  • 이탈률 감소: 사용자가 찾는 내용이 현재 페이지에 없을 때, 브레드크럼을 통해 상위 카테고리로 올라가 다른 정보를 찾도록 유도합니다.

3. 디자인 시 고려할 핵심 포인트

  • 보조적 역할: 브레드크럼은 메인 메뉴(GNB)를 대신하는 것이 아니라 보조하는 역할입니다. 너무 크거나 화려하게 디자인하지 않고 간결하게 배치합니다.
  • 위치 선정: 일반적으로 페이지 상단, 제목 바로 위나 메인 내비게이션 바 아래에 배치하는 것이 관례입니다.
  • 이동 경로 vs 계층 구조: 브레드크럼은 사용자가 실제로 '지나온 길'을 보여주기보다는, 사이트의 '논리적 계층 구조'를 보여주는 것이 훨씬 유용합니다.
  • 현재 페이지의 비활성화: 현재 머물고 있는 페이지는 클릭할 필요가 없으므로 링크를 걸지 않고 텍스트로만 처리합니다.

4. 브레드크럼의 종류

  • 위치 기반(Location-based): 가장 흔한 형태. 사이트의 고정된 계층 구조를 보여줍니다.
  • 속성 기반(Attribute-based): 이커머스에서 주로 쓰이며, 사용자가 선택한 필터(예: 남성복 > 셔츠 > 블루)를 보여줍니다.
  • 경로 기반(Path-based): 사용자가 실제로 클릭하며 들어온 순서를 보여주지만, 뒤로 가기 버튼과 기능이 겹쳐 최근에는 잘 사용되지 않습니다.

⌨️ 인풋 필드 & 플레이스홀더

인풋 필드(Input Field)와 플레이스홀더(Placeholder)는 사용자로부터 정보를 입력받는 가장 기본적인 UI 요소입니다. 회원가입, 검색, 로그인 등 서비스의 핵심 전환이 일어나는 지점에서 매우 중요한 역할을 합니다.

1. 인풋 필드 (Input Field)

사용자가 직접 텍스트 정보를 입력하는 영역입니다.

UI 구성 요소:

  • 라벨(Label): 필드가 무엇을 입력하는 곳인지 알려주는 텍스트입니다. (예: '아이디', '비밀번호')
  • 컨테이너(Container): 텍스트가 입력되는 박스 영역입니다.
  • 커서(Cursor): 입력 준비가 되었음을 알리는 깜빡이는 선입니다.

상태 디자인(States):

  • Normal: 기본 상태.
  • Focus: 마우스로 클릭하거나 탭하여 입력 중인 상태 (테두리 색상 변화 등).
  • Error: 잘못된 정보 입력 시 (주로 빨간색 테두리와 에러 메시지 노출).
  • Disabled: 입력을 막아둔 비활성화 상태 (보통 회색 배경).

2. 플레이스홀더 (Placeholder)

사용자가 입력을 시작하기 전, 인풋 필드 내부에 연하게 표시되는 힌트 텍스트입니다.

  • 역할: 어떤 내용을 입력해야 하는지 예시를 보여주거나(예: 'example@mail.com'), 입력 형식을 안내합니다(예: '하이픈(-) 없이 입력').
  • 특징: 실제 값이 아니며, 사용자가 한 글자라도 입력을 시작하면 화면에서 사라집니다.

3. 디자인 시 고려할 핵심 UX 포인트

  • 라벨은 필수입니다: 플레이스홀더를 라벨 대신 사용하는 경우가 있는데, 이는 위험합니다. 입력을 시작하면 플레이스홀더가 사라지기 때문에 사용자가 "내가 지금 뭘 적고 있었지?"라며 혼란을 느낄 수 있습니다. 라벨은 필드 외부에 항상 보여야 합니다.
  • 명확한 시각적 피드백: 현재 내가 어느 칸에 글자를 적고 있는지 'Focus' 상태를 확실히 디자인해야 합니다. (예: 테두리를 브랜드 컬러로 강조)
  • 적절한 크기: 모바일 환경을 고려하여 손가락으로 터치하기 쉽도록 필드의 높이를 충분히(최소 44~48px 이상) 확보해야 합니다.
  • 에러 메시지 배치: 단순히 테두리만 빨갛게 바꾸는 것보다, 필드 하단에 구체적인 가이드를 함께 적어주는 것이 훨씬 친절한 디자인입니다.
  • 입력에 최적화된 키보드: 모바일 앱의 경우, 이메일 필드라면 @가 포함된 키보드를 자동으로 띄워주어 수고를 덜어주어야 합니다.

📅 피커 (Picker)

피커(Picker) 디자인은 날짜, 시간, 지역과 같이 정해진 선택지 중 하나를 골라야 할 때 사용하는 UI 컴포넌트입니다. 특히 모바일 환경에서 텍스트를 직접 입력하는 번거로움을 줄여주기 위해 탄생한 디자인 요소입니다.

1. UI 디자인 특징

  • 휠(Wheel) 방식: 마치 원통을 돌리듯 위아래로 스와이프하여 값을 선택하는 방식입니다. (iOS의 기본 설정 앱 등에서 흔히 볼 수 있습니다.)
  • 드롭다운과의 차이점: 드롭다운은 선택지가 아래로 펼쳐지는 방식인 반면, 피커는 별도의 창(모달)이 뜨거나 바닥에서 올라오는 시트(Bottom Sheet) 형태가 많습니다.
  • 정돈된 위계: 현재 선택된 값이 중앙에 위치하고, 위아래 값들은 반투명하게 처리하여 '선택' 상태를 시각적으로 강조합니다.

2. 주요 종류

  • 데이트 피커 (Date Picker): 달력 형태로 날짜를 선택하거나, 연/월/일 휠을 돌려 선택합니다.
  • 타임 피커 (Time Picker): 시/분/초를 선택합니다. 오전/오후(AM/PM) 구분자가 포함됩니다.
  • 커스텀 피커: 키, 몸무게, 지역 선택 등 특정 데이터 세트를 선택할 때 사용합니다.

3. 사용 목적 및 UX 효과

  • 입력 오류 방지: "2024-02-30" 같이 존재하지 않는 날짜를 입력하는 실수를 원천적으로 차단합니다.
  • 조작 편의성: 모바일에서 작은 키보드를 두드리는 것보다 가벼운 스와이프(Swipe) 동작이 훨씬 빠르고 편리합니다.
  • 형식 통일: 서버에 데이터를 보낼 때 일정한 형식(예: YYYY-MM-DD)으로 전송할 수 있어 데이터 관리가 용이합니다.

4. 디자인 시 고려할 핵심 포인트

  • 기본값(Default Value) 설정: 사용자가 가장 많이 선택할 만한 값(예: 오늘 날짜, 현재 시간)을 미리 선택해 두어 조작을 최소화합니다.
  • 확인/취소 버튼: 선택을 완료하거나 취소할 수 있는 명확한 버튼을 함께 제공해야 합니다.
  • 모바일 네이티브 활용: 웹 브라우저나 OS가 기본으로 제공하는 피커(Native Picker)를 사용하면 사용자에게 익숙한 경험을 줄 수 있고 개발도 간편합니다.
  • 단계별 선택: 연도를 선택하면 해당 연도에 맞는 월/일이 업데이트되도록 논리적으로 연결해야 합니다.

🎓 코치마크 (Coach Mark)

코치마크(Coach Mark) 디자인은 사용자가 앱이나 서비스를 처음 이용할 때, 주요 기능이나 화면 구성을 익힐 수 있도록 화면 위에 반투명한 레이어를 덮어 특정 부분을 강조하고 설명을 덧붙이는 가이드 요소입니다.

마치 운동 경기의 코치가 선수에게 작전을 지시하듯, 인터페이스의 사용법을 직접적으로 '코칭'해준다고 해서 붙여진 이름입니다.

1. UI 디자인 특징

  • 반투명 오버레이: 기존 화면 위에 검은색이나 짙은 색의 반투명 배경을 깔아 현재 설명하는 부분 외에는 시선을 차단합니다.
  • 스포트라이트 효과: 강조해야 할 버튼이나 영역만 구멍을 뚫은 것처럼 밝게 표시하여 시선을 집중시킵니다.
  • 핸드라이팅/아이콘 활용: 딱딱한 폰트보다는 손글씨 느낌의 폰트나 화살표 아이콘을 사용하여 '친절하게 설명해주는 느낌'을 줍니다.
  • 간결한 카피: 한 번에 이해할 수 있도록 짧고 명확한 문구를 사용합니다.

2. 사용 목적 및 UX 효과

  • 신규 사용자 온보딩(Onboarding): 처음 진입한 사용자가 서비스의 핵심 기능을 빠르게 학습하고 첫 성공 경험을 갖도록 돕습니다.
  • 업데이트 안내: 기존 사용자가 익숙해진 UI가 변경되었거나 새로운 기능이 추가되었을 때 이를 직관적으로 알립니다.
  • 인지 부하 감소: 복잡한 매뉴얼을 읽지 않아도 실제 화면을 보며 즉석에서 기능을 배울 수 있습니다.

3. 디자인 시 고려할 핵심 포인트

  • 한 번에 하나씩: 너무 많은 코치마크를 한꺼번에 띄우면 사용자는 피로를 느끼고 바로 '닫기'를 눌러버립니다. 가장 중요한 기능 3~5개 이내로 제한하세요.
  • 언제든 건너뛰기(Skip): 이미 기능을 아는 사용자나 학습을 원치 않는 사용자를 위해 언제든 가이드를 종료할 수 있는 '건너뛰기'나 '다시 보지 않기' 버튼을 명확히 제공해야 합니다.
  • 맥락에 맞는 실행: 앱을 켜자마자 띄우는 것이 아니라, 사용자가 해당 기능이 있는 화면에 도달했을 때 타이밍에 맞춰 보여주는 것이 좋습니다.
  • 한 번만 보여주기: 코치마크는 학습을 위한 것이므로, 사용자가 한 번 확인했다면 다시 나타나지 않도록 설계해야 합니다.

4. 코치마크 vs 툴팁 vs 가이드 투어

  • 툴팁: 사용자가 궁금해서 아이콘에 마우스를 올릴 때 나타나는 수동적인 정보.
  • 코치마크: 시스템이 먼저 사용자에게 보여주는 능동적이고 일시적인 화면 전체 가이드.
  • 가이드 투어: 여러 개의 코치마크나 툴팁이 순차적으로 나타나며 단계별로 기능을 설명하는 과정.

코치마크 UI 예시

코치마크 데모

아래 버튼을 클릭하여 화면 위 코치마크를 띄워보세요.

이 버튼을 눌러 새 메시지를 보내보세요! 🚀

HTML
<!-- 코치마크 레이어 -->
<div class="coach-mark-overlay">
    <!-- 스포트라이트가 비춰질 영역 (위치는 JS로 조절) -->
    <div class="spotlight"></div>
    
    <!-- 설명 텍스트와 화살표 -->
    <div class="coach-content">
        <p>이 버튼을 눌러 새 메시지를 보내보세요!</p>
        <button class="close-coach">알겠어요</button>
    </div>
</div>
CSS
.coach-mark-overlay {
    position: fixed;
    top: 0; left: 0;
    width: 100%; height: 100%;
    background: rgba(0, 0, 0, 0.7); /* 반투명 배경 */
    z-index: 9999;
}

.spotlight {
    position: absolute;
    width: 60px; height: 60px;
    border-radius: 50%;
    box-shadow: 0 0 0 9999px rgba(0, 0, 0, 0.7); /* 구멍 뚫린 효과 */
    top: 20px; left: 20px; /* 실제 버튼 위치에 맞춰 조정 */
}

.coach-content {
    position: absolute;
    top: 100px; left: 50px;
    color: #fff;
    font-family: 'Arial', sans-serif;
}
jQuery
$('#coachTargetBtn').click(function() {
    $('#demoCoachMark').fadeIn();
});
$('#closeCoachBtn').click(function() {
    $('#demoCoachMark').fadeOut();
});
